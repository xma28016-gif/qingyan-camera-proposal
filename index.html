00 / PROJECT PROPOSAL

管理层决策摘要

本次立项申请解决什么问题、先投入什么、凭什么继续。

决策问题报告建议与依据
为什么做事实三位用户的记录反复出现美颜痕迹、清晰度、跨 App 修图和合照修颜差异。现有立项稿已把“提升对外发布率”列为目标；问题规模尚未量化。
先为谁做建议首期聚焦有自然成片需求的自拍用户、情侣与朋友合照用户；同时纳入帮拍者。博主作为热点和同款玩法的验证人群。
先做什么建议优先打通“拍摄—自然美颜—逐脸微调—预览—保存／分享”；以默认原生感、画质、妆容可归零和逐脸调整为核心。
如何证明有效建议主指标为有效拍摄会话保存成功率；实际对外发布单独通过自愿回访衡量。结合自然感盲测、合照各方满意度和性能稳定性共同验收。
需要投入建议12 周分阶段计划，先释放需求验证与技术验证资源；客户端、算法、设计、测试、数据及内容运营按阶段投入。金额待估时与报价后审批。
如何控制风险建议第 2、4、8、12 周设置闸门；动态妆容、人脸识别不达标时降级为静态或手动方案；核心保存与画质不得被新增能力拖累。
本次请批准待确认项目 Owner、第一阶段资源与预算上限、试点人群、指标口径及后续阶段释放规则。
01 / PROJECT PROPOSAL

项目概述

围绕移动端人像拍摄与轻量修图展开，保留轻颜相机的产品定位。

项目项定义
项目名称轻颜相机 2.0 版本迭代
产品定位建议以自然人像为基础的拍摄工具：前置自拍、后置帮拍、多人合照，拍完即可做小幅调整并保存。
核心价值自然、清楚、可控制；多人合照中每张脸都能独立照顾。
首期范围建议现有移动端核心拍摄与预览链路；操作系统、设备档位和首批机型清单待技术评审冻结。
立项状态本报告为评审稿，未取得批准；需求池 27 条记录当前显示“待评估”，不能视为已排期。
角色分工待确认产品／项目 Owner、客户端 Owner、算法 Owner、设计、测试、数据、内容运营及验收人需指定。
周期与交付建议12 周完成定义、验证、核心开发与灰度决策；交付可运行试点版本、埋点数据、效果评测与决策报告。
一句话说明
面向既想自然好看、又希望每个人都满意的拍照用户，减少夸张美颜、画质问题和反复修图造成的放弃，提升照片被保留与发布的机会。
02 / PROJECT PROPOSAL

立项背景：为什么值得现在验证

现有材料已经形成可执行需求，但尚不能证明受影响用户规模或收益量级。

判断维度已有线索立项含义
核心体验存在落差事实用户 A 希望接近原相机的自然感，并能轻微调脸；用户 B 提到滤镜发蒙、妆容不易去除。先把原生感与清晰度做透，验证是否提高成片可用性。
合照影响发布事实用户 B 提到男友被套妆；用户 C 提到放大双眼后不像本人、合照不满意便减少拍摄。合照需要独立调整与误识别纠错，不能只优化单人效果。
工作流跨工具事实用户 A 描述保存、切换软件、再保存和删除旧图；用户 B 想拍完立即修，又担心定位变杂。优先复用脸部微调，形成轻量闭环。
内容创作需要新鲜感事实用户 A、B 提到主动寻找新贴纸、新玩法；看到好看照片后还需寻找同款效果。将运营上新与同款复用作为第二阶段增长假设。
技术与业务条件待确认尚无算法基准、机型性能、埋点基线、成本与可用人力资料。先进行受控验证；现有素材与 SDK 可复用程度需评估。
立项判断：“现在做”指现在值得验证与评估，不代表已有上线时点压力或已量化的市场窗口。访谈中的其他 App 体验是当时受访者反馈，不作为当前竞品能力结论。
03 / PROJECT PROPOSAL

现有用户流程与问题定义

把“照片不发了”拆成可以定位、可以观察的损耗环节。

阶段现有行为与问题可能的损耗对应改进
拍前选效果原相机自然，但微调不足；部分滤镜只有单一质感；同款参数难寻找。在不同 App 和效果间试错。原生感档、清晰／朦胧切换、同款参数。
拍摄前置不够清楚、后置人像噪点与锐化明显；暗光难拍；帮拍不知角度。反复重拍，或直接放弃拍摄。画质优化、暗光提亮、站位线与模板。
合照修颜整张图统一加妆；多人脸难逐个调整；男生希望只做轻微处理。一人不满意，整张合照无法使用。人物方案、逐脸调节与一键纠错。
拍后检查放大后不自然；眼鼻脸型不能分开调；需跨 App 修图。返工、重复保存，增加退出机会。五官分项微调、前后对比、预览修图。
保存与发布“好看”之外还受内容、社交意愿、场景影响。保存了也未必发布。分别测量保存行为、分享动作与自愿确认发布。
问题一

自然感与清晰度冲突

目标不是一味减弱所有效果，而是保留五官细节、允许精细控制，同时保证输出画质。
问题二

合照缺少个体控制

算法给出起点，用户能逐脸更改方案；纠错必须和识别能力一起交付。
问题三

从成片到发布还有距离

拍摄工具能降低质量与操作阻力，但不能保证用户的社交发布动机。

目标用户与场景证据

当前分析表覆盖 3 位受访者，属于探索性定性材料；问答编号按该分析表保留。

用户角色典型任务访谈线索产品含义
用户 A：自然感与内容创作自拍、后置全身照、笔记封面、拍后微调。Q155：希望近乎看不出的美颜；Q180–181：后置帮拍锐化问题；Q220–221：跨 App 保存修图。原生感、画质与轻量修图优先。
用户 B：深度拍摄与合照与男友合照、朋友聚会、使用带妆滤镜、追新玩法。Q076–077：男友也被加妆；Q170–171：动态妆容跑偏；Q099：多人脸修不过来。妆容浓度归零、逐脸处理、合照差异化。
用户 C：合照参与者与帮拍者和伴侣合照、街拍帮拍、全身照。Q081–085：只推脸、眼睛略大、去痘，不要美妆；Q106：不会调角度；Q075、Q080：拍不好就不发。自然男生方案、手动纠错、帮拍参考。
证据限制：受访者包含博主、深度用户及合作相关人群，不能据此推断普通用户占比、痛点发生率或全量收益。下一阶段需补充普通用户、新用户、不同设备档位及不同合照参与者。
首期验证任务（建议）成功表现观察方式
自然自拍无需换 App，即可得到愿意保存的自然照片。任务观察、盲测、保存事件与返工次数。
情侣／朋友合照每人能单独调整；无意套妆可被及时纠正。逐人满意度、独立调整成功率、方案纠错。
朋友帮拍参考线和模板能帮助完成全身／半身构图。成片任务完成率、拍摄耗时与重拍次数。
博主同款复用照片入口能恢复可用参数，使用者可再调整。入口到达、套用成功、二次拍摄与保存。
05 / PROJECT PROPOSAL

项目目标与成功指标

先冻结可观测口径，再评估增量。以下数值均为立项建议，需在第 2 周结合基线和样本量确认。

主指标 · 建议口径
有效拍摄会话保存成功率：让用户在本次拍摄中，至少成功保存一张照片。实际对外发布作为独立结果指标跟踪。
有效拍摄会话保存成功率 = 至少产生 1 次本地保存成功的有效拍摄会话数 ÷ 有效拍摄会话数
会话建议：用户完成至少一次拍照；连续 30 分钟无操作切分会话。同一会话只计一次成功；排除测试与重复回调。最终规则由数据评审冻结。
类型指标与口径建议验收目标取数方式
核心行为保存成功会话占比；自然自拍与合照分别分层。实验组较对照组提升 ≥3 个百分点，且统计区间排除 0；最终 MDE 按基线调整。曝光分组、拍照、保存成功与错误事件。
发布结果自愿回访中确认 24 小时内已对外发布的参与者占比。作为方向性结果；需单独报告回访率、未回应者与样本偏差，不与保存率混算。知情自愿回访；无法直接获取外部平台实际发布则不宣称全量发布率。
自然感与质量同一场景盲测中，选择新方案“自然且清楚”的比例。≥70% 偏好新方案；各预设设备／场景分层无明显劣化。同光照同设备配对样片；随机展示顺序。
合照体验合照中所有参与者均给出 ≥4/5 满意度的任务占比。≥80%；手动单脸调整任务成功率 ≥95%。受控多人任务与可用性测试。
流程效率从拍完预览到保存成功的任务中位耗时。较现状下降 ≥20%，同时保存成功率不下降。任务日志与观察；按是否进入修图分层。
性能护栏保存错误、崩溃、预览帧率、耗时、发热。无未关闭严重缺陷；无崩溃会话率不低于对照 0.1 个百分点；预览帧率下降不超过 10%。机型矩阵回归＋线上监控；阈值按原能力复核。
玩法观察同款入口→套用成功→拍摄→保存的转化。先建立漏斗基线；不以入口点击率单独证明用户价值。参数恢复事件与后续拍摄保存链路。
当前基线：材料未给出保存率、发布率、活跃量或算法效果。第 1–2 周完成埋点审计和基线采集；若实验所需流量不足，延长实验或缩小结论范围，不以未显著结果宣称提升。
06 / PROJECT PROPOSAL

产品方案：三条主线，一条成片链路

功能方向来自现有立项稿与需求池；交互细节为建议方案，进入 PRD 后再冻结。

主线 A · 自然拍照

默认自然，调整有边界

原生感只匀肤色、去瑕疵；妆容可归零；五官分项微调、前后对比；覆盖前置清晰与暗光质量。
主线 B · 多人合照

每张脸独立处理

后置降噪与适度锐化；自动识别提供初始方案，逐脸微调和手动切换保留最终控制权。
主线 C · 玩法复用

看到好效果，就能复用

热点滤镜与贴纸定期上新；发布者可选同款入口；接收者一键载入滤镜＋美颜，再按自身调整。
核心交互流程（建议）
01 · 选场景自拍／合照／帮拍，默认加载自然方案。
02 · 调效果妆容浓度与五官分项控制；可按脸调整。
03 · 拍摄预览前后对比；有需要时进入轻量修图。
04 · 保存分享明确保存结果；同款入口由发布者自选。
05 · 复用反馈同款参数可恢复；不适合时再调或还原。
模块用户获得的能力交互边界与兜底（建议）
原生感轻微肤色与瑕疵处理，保留五官与脸型。新默认只在灰度组生效；旧用户已有自定义方案不直接覆盖，提供明确还原入口。
妆容与微调覆盖滤镜、风格、贴纸自带妆；眼、鼻、脸型可分开调。浓度 0 必须在所有入口一致；幅度上限降低；保存与预览效果一致。
多人脸人脸识别、各脸参数独立存储，支持点选与纠错。不把外观识别当身份判定；用户可手动选方案，低置信度使用自然中性效果。
帮拍人物轮廓、头顶线、脚底线；街拍、全身、半身 3–5 套模板。首期用固定参考模板，不承诺实时智能构图或自动拍摄。
轻量修图预览直达脸部微调，复用拍摄参数。首版不扩成全功能修图平台；支持撤销与原图对比，避免重复压缩。
同款复用滤镜＋美颜组合。只分享效果标识与允许复用的参数；不传人物识别结果；模板失效时明确提示并恢复自然档。
两处原文歧义已补齐：需求池将“滤镜=美颜”明确为“滤镜＋美颜”；男生方案在需求池与用户 C 的记录中写作“推脸”，因此本报告按“推脸、眼睛略大、去痘、不上妆”归并，强度仍需验证。

环节建议实现路线主要验证与降级

同款链路效果 ID＋允许复用的参数包；校验版本、范围和素材可用性，接收端再做逐脸适配。分享载体、落地页／深链可用性需 PoC；外部平台裁剪或去除信息时提供可行替代入口。

实验设计与验收安排

用同一用户任务、同一指标定义验证结果；不靠功能上线数量宣布成功。

阶段执行方案（建议）输出／通过条件
第 1–2 周：建立基线补齐拍摄、修图、保存、分享事件；访谈扩样建议 12–18 人，覆盖普通自拍、合照与帮拍人群。确认问题是否普遍；冻结会话口径、实验主指标、MDE 与关键设备分层。
第 3–4 周：离线与可用性同一设备／光照配对盲测；建议至少 30 位参与者，覆盖不同肤色与拍摄习惯；多人脸与动态效果专项测试。自然度、逐脸控制与性能达到建议门槛；样本数由研究与统计方案复核；人数为拟招募规模。
第 5–8 周：集成验收回归预览／输出一致、保存失败恢复、参数归零、旧用户设置、多人脸与相机前后切换。核心任务贯通；严重缺陷清零；埋点与实验分组审计通过。
第 9–12 周：随机灰度建议按符合条件的用户稳定分组，先 1% 再 5%／10%；至少覆盖两个完整自然周和足够样本。达到主指标效果与护栏才扩量；同一时段控制运营活动，避免混入其他版本变化。
第 12 周：决策复盘按意向处理原则统计全部被分配用户；分别报告模块使用、机型、自然自拍与合照结果。给出扩大／继续验证／调整／停止结论；样本不足可延期，不强制在第 12 周得出显著结论。
两组比例实验的初步样本量估算（每组）≈ 2 × (1.96＋0.84)² × p(1−p) ÷ δ²
p 为基线保存会话比例，δ 为希望检出的绝对提升；仅用于初步量级估算，需按用户聚类、重复会话、分层与流失修正。
埋点组建议事件与必要字段解释边界
分组与曝光experiment_assign、feature_exposure；匿名实验 ID、组别、App／参数版本、设备档位。以首次稳定分组为准，不能只统计实际使用功能者。
拍摄与编辑capture_success、face_adjust、edit_open、compare_view；会话 ID、前后置、手动模式。多人场景用端侧数量分桶；不上传人脸特征或性别标签。
结果行为save_success／fail、share_open、same_look_apply_success／fail。打开分享面板不等于分享成功；分享回调也不等于外部平台实际发布。
质量与稳定延迟、帧率、错误码、崩溃、模块回滚。按设备与场景分层，避免总体均值掩盖低端机劣化。

风险、降级与立项决策

每项风险给出可观察信号和处理条件，避免用范围堆叠掩盖关键不确定性。

风险预警信号应对／降级（建议）
样本偏差与问题规模不明只有合作博主强烈反馈；普通用户需求弱。扩样验证；若自然成片问题不成立，缩小或停止本期，不以 3 人推断大盘。
自然感与画质相互损伤降噪后脸糊、锐化后不自然、肤色灰暗。分场景调参；以自然＋清晰联合盲测评估；核心质量不过 G2 不进入扩量。
多人脸跟踪不稳串脸、参数漂移或一人调整影响其他人。必须先修基础绑定；低置信度重选；无法保证则先交付单人试点，合照另审。
自动方案误配误套妆、误识别、用户不能方便更改。提供手动选择、中性档、一键切换；纠错未完成不发布自动方案。
动态妆容或低端机性能转头跑偏、卡顿、发热、崩溃上升。限制妆效或动作范围、按机型降级、拍后处理；关闭单个能力而非拖累保存。
保存率与发布价值脱节保存提升，但回访发布与满意度不升。检查重复保存、误触与过度编辑；不宣称发布提升，调整问题定义。
同款参数传播失败入口被平台裁剪／屏蔽、旧版本无法还原。先验证分享载体；支持兼容与失效提示；普通保存不依赖外链。
内容与范围失控持续增加素材、复杂修图、社区或跨平台需求。新增需求说明价值、成本和闸门影响；未经范围评审不进入核心开发。
图像与人脸数据风险样片无授权、原图进入分析日志、识别标签被长期保存。建议默认端侧处理；评测样片单独授权与最小权限；留存、删除、SDK 数据行为由隐私／安全评审确认；出现泄露立即停试点。
